# 里程碑 4 · 搜索门面验收

2026-11-19，Apple M2、8 GiB、macOS 15.7.9、Swift 6.1.2。以 `f354755` 为实现基线。MB 按十进制计。

## 界面接入

`SearchEngine(dataDirectory:)` 固定从 `/` 建库，状态目录应位于本机 Data 卷。目录内使用 `index.snapshot`、`index.snapshot.changes`、`index.snapshot.budget` 和 `external-volumes/`。同一目录由一个运行中的实例负责。停止后重新启动时创建新实例。

- `EngineQuery(text:mode:column:direction:showAll:kind:offset:limit:)` 默认名称匹配、名称升序、默认可见范围、类型 `.any`、偏移 0、每页 50 条。空白查询在所有类型下均返回 0 条确切命中。
- `start()` 派发加载或扫描，`search(_:)` 同步读取已发布索引。首建期间可搜索已发布部分。手动 `rebuild()` 在串行写队列上尽快开始扫描，重建期间继续查询上一个已发布视图。命中 ID 由卷实例和行号组成。
- `onStatusChange` 与 `onIndexChange` 在后台队列回调。状态通知至少间隔 500 毫秒，索引通知至少间隔 250 毫秒。访问状态提供本机原始拒绝清单、带计数的归并清单、单独的待授权容器和各补齐来源的清单。`inaccessibleLocationsVerified` 为 `false` 时，界面显示本机“正在核对”。`recheckAccess()` 重查完整磁盘访问，核对受保护入口和已知受限位置，补扫新开放的容器，并唤醒待重试的云目录。退出调用 `stop()`，同步按原额度保存。
- 目录类型取现有属性位。文件的未下载状态沿用原有 `SF_DATALESS` 位，目录使用同一属性字节的空闲位，与待补齐状态分开。每条索引记录的快照体积和常驻属性数组大小均增加 0 字节。旧缓存中有歧义的待补目录在后台加载时只核对既知候选的元数据。查询时直接读索引元数据。

### EnginePhase 与搜索可用性

| 状态 | 何时出现 | 期间能否搜索 |
|---|---|---|
| `.starting` | 启动后正在装载并核对已有快照，或准备进入首扫 | 可调用。第一份视图发布前返回空页 |
| `.scanning(indexed:)` | 首建扫描正在进行，计数为已发布的索引条目数 | 可以，覆盖随批次扩大 |
| `.ready` | 本机已有可供查询的视图，当前没有需要单独显示的重建、外接卷扫描或云盘补齐 | 可以。普通增量、有效历史重放及延后落盘仍可在后台运行 |
| `.supplementing(name:indexed:)` | 外接卷正在建库或追平，或云提供商仍有元数据待补。计数为当前显示的卷或提供商已发布的索引条目数 | 可以，查询已发布的范围 |
| `.recovering` | 手动重建，或本机、在线外接卷因通知丢失或检查点失效而等待重扫或正在重扫。界面显示“正在更新索引” | 可以，继续查询最后一份已发布视图，新视图就绪后自动切换 |
| `.failed(reason)` | 本机核心启动、索引维护或持久化遇到错误 | 可以查询已有视图。没有可用视图时返回空页 |

手动重建在新视图发布且扫描期间的事件边界已处理后退出 `.recovering`。之后收到的普通事件和持久化仍遵循原有调度与写入额度。此时若仍有云盘或外接卷在补齐，门面转为 `.supplementing`。

### 总数口径

在同一次有序查询中，最多比请求页多取一条。查询在页尾耗尽命中时给精确总数。多取到一条时给 `offset + limit + 1` 的下限，设置 `totalIsExact = false`。当深页偏移已越过最后一个命中时，返回空页与 0 的下限。该情况不为补总数重跑查询。总数对应本次查询使用的已发布范围及开关。

### CLI 复核

从项目根目录运行已有命令行工具。在同一会话逐行输入 JSON。先用 `status` 检查状态，再输入查询。标准输出包括命中路径。

```sh
swift build -c release -j 4
.build/release/file-search engine .m2-tmp/engine-check
```

```jsonl
{"op":"status"}
{"op":"query","query":"Foundation","mode":"name","kind":"folder","limit":50}
{"op":"query","query":"/System/Library/Frameworks","mode":"path","column":"path","direction":"ascending","showAll":true,"offset":0,"limit":50}
{"op":"recheck-access"}
{"op":"quit"}
```

`query` 回应返回 `hits`、`total`、`totalIsExact` 和 `nanoseconds`。修改时间是 Unix 秒。`status` 回应包含 `status` 和用于采样的进程 `cpuSeconds`。CLI 的访问状态字段与 `EngineStatus` 同名。待授权容器位于 `pendingFullDiskAccessPaths`。CLI 也接受 `{"op":"rebuild"}`。

## 任务单 14 · 全盘访问状态

`InaccessibleLocation` 为 `Sendable, Equatable`，字段为 `path: String`、`count: Int`、`reason: InaccessibleLocation.Reason`。`EngineStatus` 提供以下属性。

| 字段 | 口径 |
|---|---|
| `rawInaccessibleLocations: [InaccessibleLocation]` | 扫描及跟踪覆盖范围内所有记录到的拒绝路径，含系统目录。按实际路径去重并排序，每条 `count` 为 1。相同路径的证据冲突时标为未知 |
| `inaccessibleLocations: [InaccessibleLocation]` | 完整的归并清单。`count` 是这一条代表的原始位置数 |
| `inaccessibleLocationCount: Int` | 原始拒绝位置总数，等于归并清单的 `count` 之和 |
| `pendingFullDiskAccessPaths: [String]` 和 `pendingFullDiskAccessCount: Int` | 出于防弹窗策略延期的逻辑容器路径及数量。Data 卷别名合计为同一个位置。单独展示，授予访问后触发补扫 |

归并在同一原因内进行。已有受限祖先吸收其后代，同一直接父目录下的两条及以上位置再归入该父目录，最后把这些归并产生的后代归入已归并的祖先。每步都累加原始计数。归并和原始清单均完整返回。展示路径代表这一分支的受限位置，实际拒绝路径见原始清单。兼容属性 `inaccessiblePaths` 投影归并路径，`awaitingFullDiskAccess` 由待授权清单是否为空得到。

扫描记录目录打开或枚举失败的路径。单条元数据失败带有名称时，记录该条目的路径，保留同目录可读取条目。系统未返回名称时，报告可定位的父目录。旧索引仍可加载，已有覆盖记录在启动核对后按实际观测补充原因。

- `likelyNeedsFullDiskAccess`。完整磁盘访问探测失败，拒绝返回 `EPERM`，且路径位于 Apple 说明的当前用户隐私范围内。包括桌面、文稿、下载、iCloud Drive 及邮件、信息、Safari 数据。在这些条件下预计授权可恢复。[Apple 文件访问控制](https://support.apple.com/guide/security/controlling-app-access-to-files-secddd1d86a6/web) · [Apple 隐私与安全性设置](https://support.apple.com/guide/mac-help/mchl211c911f/mac)
- `filePermissions`。实际目录读取或条目元数据返回 `EACCES`。Apple 将其归为 BSD 权限或 ACL 拒绝，需具备相应文件权限，完整磁盘访问本身不会改变该权限。[Apple DTS 文件系统权限说明](https://developer.apple.com/forums/thread/678819)
- `unknown`。其余 `EPERM`、无可用错误码或有冲突的记录。`EPERM` 可能来自多种限制。`/System` 等路径前缀本身不足以判定 SIP 导致读取失败。[Apple DTS 文件系统权限说明](https://developer.apple.com/forums/thread/678819) · [Apple 系统完整性保护说明](https://support.apple.com/guide/security-pdf/system-integrity-protection-secb7ea06b49/1/web/1)

## 任务单 15 · 类型筛选、补齐进度与拒绝清单核对

### 类型筛选

公开接口为 `public enum EngineKind: String, Sendable, CaseIterable` 和 `EngineQuery.kind: EngineKind`，默认为 `.any`。核心对类型、名称或路径词与可见范围取交集，再按所选列和方向做全局分页。`total` 和 `totalIsExact` 仍使用同一页的一条额外命中判断。空白文本在所有类型下均返回空页和确切总数 0。

| 值 | 判定 |
|---|---|
| `any` | 不限制类型 |
| `folder` | 索引记录的目录位，包括 `.app` 和文稿包目录 |
| `document` | `csv`、`doc`、`docm`、`docx`、`dps`、`epub`、`et`、`key`、`md`、`numbers`、`odp`、`ods`、`odt`、`pages`、`pdf`、`ppt`、`pptm`、`pptx`、`rtf`、`tsv`、`txt`、`wps`、`xls`、`xlsm`、`xlsx` |
| `image` | `3fr`、`arw`、`avif`、`bmp`、`cr2`、`cr3`、`dng`、`gif`、`heic`、`heif`、`icns`、`ico`、`j2k`、`jp2`、`jpeg`、`jpg`、`nef`、`nrw`、`orf`、`pef`、`png`、`psd`、`raf`、`raw`、`rw2`、`srf`、`svg`、`tif`、`tiff`、`webp` |
| `audio` | `aac`、`aif`、`aiff`、`alac`、`flac`、`m4a`、`mid`、`midi`、`mp3`、`ogg`、`opus`、`wav`、`wma` |
| `video` | `3gp`、`avi`、`flv`、`m2ts`、`m4v`、`mkv`、`mov`、`mp4`、`mpeg`、`mpg`、`mts`、`webm`、`wmv` |
| `archive` | `7z`、`bz2`、`dmg`、`gz`、`iso`、`rar`、`tar`、`tbz`、`tbz2`、`tgz`、`txz`、`xar`、`xz`、`zip`、`zst` |
| `application` | 目录位有效，末尾扩展名为 `app` |

扩展名使用文件名最后一个非首字符的点之后的部分，ASCII 大小写等价。`.tar.gz` 按 `gz` 匹配。按扩展名的类别也包括符合扩展名的包目录。查询使用索引属性和名称，不读取正文或 UTI。

索引属性字节已用去七位。准备基准或增量视图时，核心从原始文件名派生每行一个字节的内存类型表，并在原有匹配路径读取该表。目录筛选直接读取目录位。旧基准和增量日志格式沿用，历史快照载入时派生同样的类型表，每条持久记录增加 0 字节，也无需为类型更新整档。约 195 万行的本机基准需要约 1.95 MB 的类型表，增量和外接卷按准备的行数计。

外接卷每批发布时准备该批的名称排序和类型表，让补齐中的查询使用与完整视图相同的核心匹配路径。初轮实测在外接卷已发布 50 万余条且仍在扫描时，原来的未准备视图回退到 Swift 逐行筛选，无类型限制的名称查询 P95 为 628.342 ms，带类型为 50.269 至 297.334 ms。这轮读数用于定位后续修正。

### 补齐进度与访问状态

`EnginePhase.supplementing(name: String, indexed: Int)` 返回当前显示来源。外接卷直接读取该卷已发布视图的行数。云盘以提供商根为单位累计已发布的条目，含提供商目录和下属条目，现有条目计入起点，增删和屏蔽随视图更新。`onStatusChange` 最快每 500 毫秒发一次并交付最新状态。`scanning(indexed:)` 保留首建已发布总数的口径。CLI 的补齐状态提供 `name` 和 `indexed`。

旧门面把每份发布视图的拒绝数据直接输出。刚加载快照时，记录中可能仍有尚待重枚举的旧拒绝。首建分批发布、日志追平和外接卷补扫又会逐步更新清单。另有一条确定的漏计路径：只重扫 Data 卷时，旧实现保留了只读系统卷的索引行，却没有保留该卷的拒绝记录。这里的时序和丢失机制可从旧代码及回归测试确认，已授权 App 的 249 和 196 仍需该 App 复现才能逐项归因。

现在公开 `EngineStatus.inaccessibleLocationsVerified: Bool`。启动期间等待本机扫描或已有快照的访问复核、历史追平和首次外接盘发现，其后等待在线外接盘完成。发生重扫或调用 `recheckAccess()` 后，清单在相应核对完成前暂时返回空数组和 0，界面以标志决定是否展示数字。已延期的容器仍单独计数。云盘尚未请求到的元数据保留为待补状态，后续观察到的新拒绝可以正常更新清单。

启动重新观察快照中的已知拒绝，以及当前用户的受保护入口。权限重查重新探测授权、核对上述入口和已知拒绝，并对重新开放的目录恢复可读后代。仍被拒绝的父目录以本次观察为证据，其下无法继续观测的历史拒绝清除。Data 局部重扫保留只读系统卷已核对的覆盖证据，与 Data 新扫描的结果合并。退出或冷启动本身可以保留搜索所需的基准与日志。

## 任务单 16 · 本机、外接卷和云盘分别核对

`EngineStatus.inaccessibleLocationsVerified`、`inaccessibleLocations`、`rawInaccessibleLocations` 和原始总数现在表示本机已核对范围。归属已能识别的云提供商拒绝在该提供商的状态中展示。无法读取提供商上层容器时，容器本身仍在本机清单中。

新增 `EngineStatus.localIndexedCount: Int` 和 `EngineStatus.sources: [EngineSourceStatus]`。`localIndexedCount` 是本机跟踪器已发布的条目数，包含本机已发布的云盘条目。全局 `indexedCount` 等于该数加上所有在线外接卷的 `indexed`。云盘条目已经包含在本机跟踪器内。

| `EngineSourceStatus` 字段 | 类型与口径 |
|---|---|
| `id`、`name` | `String`。来源标识与显示名。外接卷标识与 `EngineHit.volumeID` 对应，云提供商标识使用提供商根 |
| `kind` | `EngineSourceStatus.Kind`，取 `externalVolume` 或 `cloudProvider` |
| `indexed` | `Int`，此来源当前已发布、可以查询的条目数 |
| `inaccessibleLocationsVerified` | `Bool`。外接卷按自己的扫描与追平状态判定，云提供商按此来源当前是否还有待补目录判定 |
| `inaccessibleLocations`、`rawInaccessibleLocations` | `[InaccessibleLocation]`。相应来源核对完成后给出归并与原始清单。核对中均为空 |
| `error` | `String?`，外接卷失败时返回错误；界面可展示该来源失败 |
| `scan` | `ExternalScanStatistics?`，外接卷扫描诊断，含实际读取和恢复数量、各阶段耗时及检查点写入量 |

界面进入本机已核对状态，立即展示本机清单。再按 `sources` 展示已核对来源的结果，以及仍在补齐的来源名称与当前条目数。例如“某卷仍在补充，完成后可能增加”。`EnginePhase.supplementing(name: String, indexed: Int)` 延用现有签名；其数字与同一次状态中的对应来源一致。多个来源独立推进时，状态条可显示其中一个，完整列表读取 `sources`。待授权容器仍单独展示。

旧版的 3,471 是该盘越过首批 2,048 行门槛时一起发布的条目数。后续按约 20,000 条的批量阈值发布，读取在途或批量阈值尚未达到时会维持首批数字。该 exFAT 卷原先没有可复用的外接卷索引，重启后重复出现同一首批。旧版同一次状态读取也从同一外接卷视图计算其数字和全局数。授权预览 App 中出现的全局增长与所选来源长期不一致，需要在 App 同时记录 `localIndexedCount` 与各来源的 `indexed` 才能定位。新版按时间和增量都能触发卷视图发布，并提供同一来源的已发布计数及恢复统计。

- 在 `onExternalVolumesChange` 后重新读取 `externalVolumes` 和设置错误。挂载登记可先于本机索引载入完成。在线或加入状态可用于立即展示设备，搜索计数从索引视图发布后才开始反映可搜索范围。
- `progress == .restoring` 显示正在恢复已收录的内容，`.scanning` 显示正在读新内容。旧的 `isScanning` 在这两种活动阶段都为 `true`。`indexedCount` 是当前可查询的数量，离线或未加入时为 0。恢复期可能从根指纹已核验的本机日志先发布可搜索视图，此时对应来源的 `inaccessibleLocationsVerified` 仍为 `false`。后续目录核验发现变化，数字可能随视图撤回而减少。
