# 里程碑 4 · 搜索门面验收

2026-11-19，Apple M2、8 GiB、macOS 15.7.9、Swift 6.1.2。以 `f354755` 为实现基线。MB 按十进制计。

## 界面接入

`SearchEngine(dataDirectory:)` 固定从 `/` 建库，状态目录应位于本机 Data 卷。目录内使用 `index.snapshot`、`index.snapshot.changes`、`index.snapshot.budget` 和 `external-volumes/`。同一目录由一个运行中的实例负责。停止后重新启动时创建新实例。

- `EngineQuery(text:mode:column:direction:showAll:offset:limit:)` 默认名称匹配、名称升序、默认可见范围、偏移 0、每页 50 条。空白查询返回 0 条确切命中。
- `start()` 派发加载或扫描，`search(_:)` 同步读取已发布索引。首建期间可搜索已发布部分。手动 `rebuild()` 重用恢复、扫描和写入额度逻辑，重建期间继续查询旧视图。命中 ID 由卷实例和行号组成。
- `onStatusChange` 与 `onIndexChange` 在后台队列回调。后者合并连续变更，两个通知至少间隔 250 毫秒。权限列表去重并保留最上层受限目录，展示最多 200 条。`recheckAccess()` 重试核心记录的受限目录及待重试的云目录。退出调用 `stop()`，同步按原额度保存。
- 目录类型取现有属性位。文件的未下载状态沿用原有 `SF_DATALESS` 位，目录使用同一属性字节的空闲位，与待补齐状态分开。每条索引记录的快照体积和常驻属性数组大小均增加 0 字节。旧缓存中有歧义的待补目录在后台加载时只核对既知候选的元数据。查询时直接读索引元数据。

### 总数口径

在同一次有序查询中，最多比请求页多取一条。查询在页尾耗尽命中时给精确总数。多取到一条时给 `offset + limit + 1` 的下限，设置 `totalIsExact = false`。当深页偏移已越过最后一个命中时，返回空页与 0 的下限。该情况不为补总数重跑查询。总数对应本次查询使用的已发布范围及开关。

### CLI 复核

从项目根目录运行已有命令行工具。在同一会话逐行输入 JSON。先用 `status` 检查状态，再输入查询。标准输出包括命中路径。

```sh
swift build -c release -j 4
.build/release/file-search engine .m2-tmp/engine-check
```

```jsonl
{"op":"status"}
{"op":"query","query":"Foundation","mode":"name","limit":50}
{"op":"query","query":"/System/Library/Frameworks","mode":"path","column":"path","direction":"ascending","showAll":true,"offset":0,"limit":50}
{"op":"recheck-access"}
{"op":"quit"}
```

`query` 回应返回 `hits`、`total`、`totalIsExact` 和 `nanoseconds`。修改时间是 Unix 秒。`status` 回应包含 `status` 和用于采样的进程 `cpuSeconds`。CLI 也接受 `{"op":"rebuild"}`。

## 自动化与实机

运行 `swift test -c release -j 4 --disable-xctest --enable-swift-testing`，56 项全部通过，其中原有 53 项。本次增加了门面的分页与持久化、权限重查与手动重建、回调合并、类型及卷标志覆盖。

先从空目录建立一份真实全盘索引，再由最终构建载入这份基准与日志，串行运行查询、元数据抽查和监听窗口。本轮继续使用当前可读范围。查询为 50 条首屏、开启显示全部。每种模式 10 类可复现输入，各取 20 次，包含高命中、稀有、零命中、路径跨分量和多词，轮换四列与两种方向。预热列排序后采样。P95 取排序后第 `ceil(0.95 × n)` 项，计时包含总数和 `EngineHit` 生成，JSON 编码在计时区间外。

| 查询 | 请求数 | 精确总数 / 下限 | P95 |
|---|---:|---:|---:|
| 名称 | 200 | 40 / 160 | 9.825 ms |
| 路径 | 200 | 60 / 140 | 13.685 ms |
| 两种合计，含总数 | 400 | 100 / 300 | 13.081 ms |

随后用同一持久索引及同一组请求串行复跑现有 `track`，仅返回页面，名称和路径各 200 次的 P95 为 10.146 ms 和 14.789 ms。两次运行期间各自应用实时事件，数据随时间更新。门面的单次首次列排序预热耗时为 27.227 至 253.844 ms。

测量开始时收录 2,183,275 条，受限目录展示达到 200 条上限。用 `lstat` 核对 20 条命中的目录类型、`SF_DATALESS` 及设备归属，三项均一致。样本包含 5 个目录、10 个普通文件和 5 个符号链接，普通文件中有 5 个实际未下载的云占位。云盘测试只读元数据，当时没有可纳入本轮抽查的在线外接卷，真实外接卷正例未测。外接标识和卷实例 ID 包含在自动化覆盖中。

窗口首尾均在后台补齐，受测持久文件合计增长 185,453 B。非监听阶段在进程启动约 1.36 秒采到物理占用 210.618 MB，高于 200 MB。这段包含热加载和首次列排序预热。
