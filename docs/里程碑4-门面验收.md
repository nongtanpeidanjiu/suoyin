# 里程碑 4 · 搜索门面验收

2026-11-19，Apple M2、8 GiB、macOS 15.7.9、Swift 6.1.2。以 `f354755` 为实现基线。MB 按十进制计。

## 界面接入

`SearchEngine(dataDirectory:)` 固定从 `/` 建库，状态目录应位于本机 Data 卷。目录内使用 `index.snapshot`、`index.snapshot.changes`、`index.snapshot.budget` 和 `external-volumes/`。同一目录由一个运行中的实例负责。停止后重新启动时创建新实例。

- `EngineQuery(text:mode:column:direction:showAll:offset:limit:)` 默认名称匹配、名称升序、默认可见范围、偏移 0、每页 50 条。空白查询返回 0 条确切命中。
- `start()` 派发加载或扫描，`search(_:)` 同步读取已发布索引。首建期间可搜索已发布部分。手动 `rebuild()` 在串行写队列上尽快开始扫描，重建期间继续查询上一个已发布视图。命中 ID 由卷实例和行号组成。
- `onStatusChange` 与 `onIndexChange` 在后台队列回调。后者合并连续变更，两个通知至少间隔 250 毫秒。访问状态提供全盘原始拒绝清单、带计数的归并清单和单独的待授权容器清单。`recheckAccess()` 重查完整磁盘访问，补扫新开放的容器，并重试核心记录的受限位置及待重试的云目录。退出调用 `stop()`，同步按原额度保存。
- 目录类型取现有属性位。文件的未下载状态沿用原有 `SF_DATALESS` 位，目录使用同一属性字节的空闲位，与待补齐状态分开。每条索引记录的快照体积和常驻属性数组大小均增加 0 字节。旧缓存中有歧义的待补目录在后台加载时只核对既知候选的元数据。查询时直接读索引元数据。

### EnginePhase 与搜索可用性

| 状态 | 何时出现 | 期间能否搜索 |
|---|---|---|
| `.starting` | 启动后正在装载并核对已有快照，或准备进入首扫 | 可调用。第一份视图发布前返回空页 |
| `.scanning(indexed:)` | 首建扫描正在进行，计数为已发布的索引条目数 | 可以，覆盖随批次扩大 |
| `.ready` | 本机已有可供查询的视图，当前没有需要单独显示的重建、外接卷扫描或云盘补齐 | 可以。普通增量、有效历史重放及延后落盘仍可在后台运行 |
| `.supplementing(name:)` | 外接卷正在建库或追平，或云提供商仍有元数据待补 | 可以，查询已发布的范围 |
| `.recovering` | 手动重建，或本机、在线外接卷因通知丢失或检查点失效而等待重扫或正在重扫。界面显示“正在更新索引” | 可以，继续查询最后一份已发布视图，新视图就绪后自动切换 |
| `.failed(reason)` | 本机核心启动、索引维护或持久化遇到错误 | 可以查询已有视图。没有可用视图时返回空页 |

手动重建在新视图发布且扫描期间的事件边界已处理后退出 `.recovering`。之后收到的普通事件和持久化仍遵循原有调度与写入额度。此时若仍有云盘或外接卷在补齐，门面转为 `.supplementing`。

### 总数口径

在同一次有序查询中，最多比请求页多取一条。查询在页尾耗尽命中时给精确总数。多取到一条时给 `offset + limit + 1` 的下限，设置 `totalIsExact = false`。当深页偏移已越过最后一个命中时，返回空页与 0 的下限。该情况不为补总数重跑查询。总数对应本次查询使用的已发布范围及开关。

### CLI 复核

从项目根目录运行已有命令行工具。在同一会话逐行输入 JSON。先用 `status` 检查状态，再输入查询。标准输出包括命中路径。

```sh
swift build -c release -j 4
.build/release/file-search engine .m2-tmp/engine-check
```

```jsonl
{"op":"status"}
{"op":"query","query":"Foundation","mode":"name","limit":50}
{"op":"query","query":"/System/Library/Frameworks","mode":"path","column":"path","direction":"ascending","showAll":true,"offset":0,"limit":50}
{"op":"recheck-access"}
{"op":"quit"}
```

`query` 回应返回 `hits`、`total`、`totalIsExact` 和 `nanoseconds`。修改时间是 Unix 秒。`status` 回应包含 `status` 和用于采样的进程 `cpuSeconds`。CLI 的访问状态字段与 `EngineStatus` 同名。待授权容器位于 `pendingFullDiskAccessPaths`。CLI 也接受 `{"op":"rebuild"}`。

## 任务单 14 · 全盘访问状态

`InaccessibleLocation` 为 `Sendable, Equatable`，字段为 `path: String`、`count: Int`、`reason: InaccessibleLocation.Reason`。`EngineStatus` 提供以下属性。

| 字段 | 口径 |
|---|---|
| `rawInaccessibleLocations: [InaccessibleLocation]` | 扫描及跟踪覆盖范围内所有记录到的拒绝路径，含系统目录。按实际路径去重并排序，每条 `count` 为 1。相同路径的证据冲突时标为未知 |
| `inaccessibleLocations: [InaccessibleLocation]` | 完整的归并清单。`count` 是这一条代表的原始位置数 |
| `inaccessibleLocationCount: Int` | 原始拒绝位置总数，等于归并清单的 `count` 之和 |
| `pendingFullDiskAccessPaths: [String]` 和 `pendingFullDiskAccessCount: Int` | 出于防弹窗策略延期的逻辑容器路径及数量。Data 卷别名合计为同一个位置。单独展示，授予访问后触发补扫 |

归并在同一原因内进行。已有受限祖先吸收其后代，同一直接父目录下的两条及以上位置再归入该父目录，最后把这些归并产生的后代归入已归并的祖先。每步都累加原始计数。归并和原始清单均完整返回。展示路径代表这一分支的受限位置，实际拒绝路径见原始清单。兼容属性 `inaccessiblePaths` 投影归并路径，`awaitingFullDiskAccess` 由待授权清单是否为空得到。

扫描记录目录打开或枚举失败的路径。单条元数据失败带有名称时，记录该条目的路径，保留同目录可读取条目。系统未返回名称时，报告可定位的父目录。旧索引仍可加载，已有覆盖记录在启动核对后按实际观测补充原因。

- `likelyNeedsFullDiskAccess`。完整磁盘访问探测失败，拒绝返回 `EPERM`，且路径位于 Apple 说明的当前用户隐私范围内。包括桌面、文稿、下载、iCloud Drive 及邮件、信息、Safari 数据。在这些条件下预计授权可恢复。[Apple 文件访问控制](https://support.apple.com/guide/security/controlling-app-access-to-files-secddd1d86a6/web) · [Apple 隐私与安全性设置](https://support.apple.com/guide/mac-help/mchl211c911f/mac)
- `filePermissions`。实际目录读取或条目元数据返回 `EACCES`。Apple 将其归为 BSD 权限或 ACL 拒绝，需具备相应文件权限，完整磁盘访问本身不会改变该权限。[Apple DTS 文件系统权限说明](https://developer.apple.com/forums/thread/678819)
- `unknown`。其余 `EPERM`、无可用错误码或有冲突的记录。`EPERM` 可能来自多种限制。`/System` 等路径前缀本身不足以判定 SIP 导致读取失败。[Apple DTS 文件系统权限说明](https://developer.apple.com/forums/thread/678819) · [Apple 系统完整性保护说明](https://support.apple.com/guide/security-pdf/system-integrity-protection-secb7ea06b49/1/web/1)
