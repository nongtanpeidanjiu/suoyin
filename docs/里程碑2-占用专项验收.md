## 实现取舍

- 用 `realpath(3)` 统一根目录和自有目录拼写。自动化只读验证 macOS 的 `/tmp` 别名与 `/private/tmp` 下的事件边界和排除规则。会写文件的跟踪测试在项目 `.m2-tmp/` 进行。
- 普通文件按目标路径核对。新建、删除、改名的父目录按批去重，各补一次元数据核对。首次内容观测及时应用，随后同一路径在 30 秒内合并，待办限制持久检查点。单独的 inode 元数据标志也可能表示权限等变化，走既有目录降频。目录自身事件另核对访问能力，受限或与索引矛盾时走复查。
- 匹配继续按空格分词、逐词子串匹配，保留 NFC 与英文大小写规则。仅 NFC 结果改变的非 ASCII 名称保存折叠键。ASCII 大小写在查询和排序中即时折叠，池扫描使用 NEON 筛选候选。
- 增量日志格式、索引记录结构和合并流程沿用现有实现。全盘只用常规文件元数据接口，扫描最多 4 个线程。报告中的查询回放、慢参照和全盘监听均串行运行。

建议下一轮先定位 FSEvents 在有效热重放后出现 `UserDropped` 的条件，复测时记录回调批次大小和交付时延，再按相同口径跑一个连续有效的 900 秒窗口。

### 残留索引修正

合并会为缺少已索引父项的编辑建立独立绝对路径锚点。部分锚点身处 Data 卷范围，却没有可沿父链追溯的 Data 根，导致恢复时被误当作封闭系统卷数据保留。修正后在提取封闭卷时也按锚点的绝对路径排除 Data 范围。最终版本还将退出时最后一批监听回调纳入检查点处理。

随后用最终构建重新打开同一基准和日志。启动检查到失效位置后恢复 Data 卷。旧视图在扫描期间仍可查询。切换后，已删除压力树的路径查询返回 0 行，五个树外样本的路径、大小和修改时间与 `lstat` 一致。恢复耗时 13.518 秒，进程物理占用最高 252.94 MB，追平后为 123.93 MB。既有 24 小时额度已用完，整档写入和进程写入均为 0，状态已追平且退出成功。此定向复核沿用压力试验的基准，没有再次创建压力文件。它覆盖残留索引修正和恢复内存目标，压力窗口的终态和五分钟资源判定仍见上表。

自然压测未触发丢失，另以里程碑 3 的候选构建在自有快照上向全盘跟踪器注入一条 `MustScanSubDirs | UserDropped`。完整经历待恢复、整卷重建和再次追平。恢复 1 次，14.668 秒，恢复区间写入 16,384 B。进程累计写入 987,136 B，恢复后树外五项和已删压力树抽查正确。追平后 300.003 秒内最高采样物理占用 134.547 MB，平均单核 1.113%。该构建在同窗继续云盘补齐，CPU 项未达标。后续调整与最终复测见[里程碑 3 验收](里程碑3-云盘与外接盘验收.md)。

700 ms 节流构建的一次补充注入试跑从旧检查点启动。历史回调达到本地收件上限，先自动恢复 1 次。之后的注入进入生产设定的 600 秒恢复冷却，验收脚本等待 150 秒后结束，本次未形成第二个注入后五分钟窗口。改用无注入的常规监听独立复测，五分钟平均单核 0.588%，最高物理占用 133.482 MB。

## 任务单 22 · 安静状态 CPU 与采样口径

同机交错复测未发现安静状态的 CPU 随版本上升。历史验收缺少同窗事件计数，因此无法重建每轮的负载组成。本轮区分实际事件处理和无事件基础，并统一采样口径。

### 同机版本对照

四版使用同一个含 1,950,147 条基准记录的本机快照和同源增量日志，各从独立副本热启动。四个 180 秒全盘实时监听窗口按 `9deb3f8`、`14cce73`、`f3e0688`、`3c55568` 的顺序串行运行。各从追平后第 8 秒开始计时，启用原有云盘调度，禁用真实外接发现，未发送查询。收件数是窗口中 FSEvents 交付的事件行数，可能包含同一文件的多次事件，也包含收到后被作用域过滤的事件。内存峰值由另一进程通过 `proc_pid_rusage` 采样。测试进程每 30 秒记录一次自己的 CPU 时间和累计业务计数。

基础开销用相同全盘快照和相同跟踪器单独测量。追平后让真实监听只接收项目内空目录的事件，并关闭云任务。分别使用事件、核验、发布、定时器执行次数以及进程唤醒计数核对空窗。此控制用于比较无事件、无云任务的运行底噪。全盘窗口保留真实后台事件，因此两类窗口分别报告。

四个自然窗口均无事件丢失、云任务失败、整卷恢复及基准整档重写。实际应用批的原始 CPU 用量为 **20.66 至 22.91 毫秒/批**，接近程度高于按原始事件数归一化的结果。以 `9deb3f8` 和 `f3e0688` 为例，前者核对了 262 个文件、104 个目录和其中 17 个递归目录，后者核对了 73 个文件、35 个目录和 0 个递归目录。原始事件的合并程度与单次工作量随后台活动变化。

最新版的 180 秒无事件窗口中，无登记和有一条未加入卷登记的基线分别为 **0.0278%** 和 **0.0274%**，相差 **0.0004 个百分点**。两组文件事件、云任务及目录核验均为 0。峰值物理占用为 133.14 MB 和 133.47 MB，无整档重写。两组各有一次在启动阶段预约的日志同步，分别写入 524,288 B 和 507,904 B，同时各有一次门面刷新与延后状态通知。60 秒以后平均单核分别为 0.0015% 和 0.0020%，两组均未再执行核心定时器处理。测试自身每 30 秒取样一次，两组的内核中断唤醒计数均增加 8。

归一化先从全盘 CPU 秒扣掉同版的无事件 CPU 秒。三份旧版的无事件对照为 90 秒，用 60 秒后测得的速率补足到 180 秒，保留一次启动日志同步。剩余 CPU 秒除以全盘收件量再乘 1,000。自然窗口的收件内容没有逐条配对，`14cce73` 的剩余 CPU 还含两个云目录。最近三版按有效应用批计为 21.51–22.02 毫秒，单按事件行数折算容易受合并程度影响。最新一版比 `3c55568` 少 40 行收件，却多应用 11 批，并多做 9 个目录核验，解释了时段之间每千事件的成本差异。

### 历史采样口径核查

任务单 19 从目标进程外读取进程资源。任务单 20 和 21 的监听脚本在目标进程内以约 10 Hz 调用 `ChangeTracker.processMetrics()`，会执行 `malloc_zone_statistics`。该开销计入了当时的 CPU 均值。历史数据缺少同窗事件计数，无法进一步把三个历史均值分别拆成采样、事件和云任务用量。

在同一版 `f3e0688`、登记一条未加入卷且无事件的条件下，取启动日志同步前的窗口重现进程内采样。15.007 秒内调用 145 次，平均单核 **0.0797%**。同一构建原先只在窗口边界取样的首 30 秒为 **0.0030%**。两窗均无事件、云任务或日志同步，差 **0.0767 个百分点**。

### 后续验收口径

- 同一份快照、相同预热和测量长度，至少保留 180 秒的真实全盘监听数据。两个边界记录用户态和系统态 CPU 秒、墙钟、FSEvents 收件、实际应用批、直接文件和目录核验、云完成、失败与待办，另记外接卷登记数和加入数。报告物理峰值、进程写盘量及基准整档重写次数。
- CPU 和内存用进程外 `proc_pid_rusage` 采集，或仅在首尾读取被测进程的 CPU 和状态计数。避免在被测窗口内高频调用包含 `malloc_zone_statistics` 的 `ChangeTracker.processMetrics()`。需要采集堆统计时单独开诊断窗口。
- 无事件基础另用固定的零收件、零云任务窗口记录；有一条注入的未加入登记和无登记各做一个 180 秒对照。自然全盘若仍有后台活动，公布其数据并说明未取得零收件的全盘窗。每千个事件用扣除基础后的 CPU 秒计算，同时给出应用批与云任务数。没有事件时该开销不适用，有云任务时注明它混在剩余成本中。

首次复跑发现既有云盘用例收到补齐通知后可能早于本机核验状态发布。该用例现在等待同一个状态快照同时报告本机已核验、云来源仍在补齐，然后释放注入的目录任务。

最终 Release 测试 **80 项通过**，其中多来源对照 **288 组一致**。独立查询回放 **2,190 次一致**，含 1,680 次本机和 510 次合成索引查询。
